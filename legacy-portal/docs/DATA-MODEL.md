# Data model
Nine collections: `businesses`, `sources`, `researchSignals`, `opportunities`, `campaigns`, `campaignProspects`, `interactions`, `reports`, `integrationSettings`. Each record has a string `id`. Linked records use `business_id` and `campaign_id`. Records include timestamps where created through the UI. Business `name`, `legalName`, `nzbn`, `registration`, `category`, `size`, `region`, `lifecycle`, `industry`, `website`, `verification`, `confidence`, `reviewDate`, `researchDate`, `description`, `notes` are editable. `sources` records preserve URLs and user-entered provenance. `opportunities` are append-only assessment snapshots with a human explanation. `campaignProspects` carry pipeline status, follow-up and notes separately from the business profile. `researchSignals`, `interactions`, and `integrationSettings` are reserved structures for future workflows; no UI to manage them in v0.1.

Import validation checks collection shape, record IDs and duplicate IDs; it is not a complete schema validator. Only import trusted backups. Never treat a local verification label as independent validation.
